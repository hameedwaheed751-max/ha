# قسم «المشتريات»: دليل متاجر الوكلاء (Agent Stores Directory)

Design spec — 2026-11-12

## 1. الهدف (Intent)

يرغب المستخدم (الأدمن) أن يتمكّن **أي وكيل** من تسجيل متجره الإلكتروني
لبيع الأجهزة (راوترات، ONU، كاميرات، كيبلات…) داخل التطبيق، فيظهر متجره
لبقية الوكلاء في قسم **«المشتريات»**، ويُفتح داخل التطبيق لعرض أجهزته.

مثال واقعي لمتجر وكيل: `https://shams-ftth.vercel.app` — تطبيق ويب (SPA)
يعرض منتجات ويُرسل الطلب عبر واتساب، **بلا API عام للمنتجات**.

**النتيجة المرجوة:** دليل متاجر مشترك، كل وكيل يضيف متجره (بموافقة الأدمن)،
والبقية يتصفّحونه ويفتحون المتجر داخل التطبيق.

**الجمهور:** الوكلاء (يعرضون متاجرهم ويتصفّحون متاجر غيرهم).

## 2. القرارات المعتمدة (من المستخدم)

- **المسار:** دليل متاجر + فتح داخل التطبيق (WebView) — لا سحب منتجات ولا
  سلة/دفع داخل التطبيق (الطلب يبقى على موقع كل وكيل، مثل واتساب في shams).
- **الاعتماد:** متجر الوكيل **لا يظهر إلا بعد موافقة الأدمن**.
- **نقطة الدخول:** عنصر **«المشتريات»** في **الشريط السفلي مكان «التقارير»**
  (الفهرس 3). التقارير تبقى متاحة من القائمة الجانبية («تقارير سريعة»،
  «التقارير الحسابية») فلا يُفقد الوصول إليها.

## 3. القيود (Why these choices)

- مواقع الوكلاء مخصّصة وبلا API موحّد، فالسحب الموحّد للمنتجات غير ممكن
  موثوقاً؛ WebView يعرض متجر كل وكيل كما هو.
- `webview_flutter` متوفّر أصلاً كاعتماد في المشروع. على نسخة الويب
  (GitHub Pages) لا يعمل WebView جيداً، فنفتح الرابط في **تبويب خارجي**.
- نعيد استخدام نمط `sasDirectory` (الخدمة + القواعد + نافذة الإضافة)
  لتقليل المخاطر والاتّساق. راجع `lib/services/sas_directory_service.dart`.

## 4. نموذج البيانات (Firebase RTDB)

عقدة جديدة `stores/{key}` حيث `key` = معرّف Firebase push (فريد لكل متجر؛
الوكيل قد يملك أكثر من متجر لكن MVP يكتفي بواحد ويمكن التوسّع لاحقاً).

| الحقل | النوع | ملاحظات |
|------|------|---------|
| `name` | String (1..80) | اسم المتجر |
| `url` | String (1..300) | رابط https للمتجر |
| `logoUrl` | String? (≤500) | شعار اختياري؛ وإلا أيقونة الموقع (favicon) |
| `whatsapp` | String? (≤30) | رقم واتساب اختياري للطلب |
| `description` | String? (≤200) | وصف قصير اختياري |
| `ownerUid` | String | uid الوكيل المالك (للتعديل/الحذف والإسناد) |
| `ownerName` | String (≤80) | اسم المكتب للعرض |
| `approved` | bool | يبدأ false؛ **لا يضبطه true إلا الأدمن** |
| `createdAt` / `updatedAt` | number | ServerValue.timestamp |

**لا يُخزَّن أي اعتماد (كلمة مرور/توكن)** — معلومات متجر عامة فقط.

## 5. قواعد الأمان (`database.rules.json` → `stores`)

على نمط كتلة `sasDirectory`:

- `.read`: الأدمن **أو** دور الوكيل (`root.child('agents/$uid/profile/role')`).
- `stores/$key`:
  - `.write`:
    - الأدمن: كتابة كاملة (اعتماد/تعديل/حذف أي متجر).
    - الوكيل (دور agent): يكتب/يعدّل/يحذف **متجره فقط** —
      `newData.child('ownerUid').val() === auth.uid` وعلى الحذف
      `data.child('ownerUid').val() === auth.uid`، **ولا يضبط**
      `approved` إلى true (يبقى false من الوكيل).
  - `.validate`: `hasChildren(['name','url','ownerUid','ownerName','approved'])`؛
    `url` يبدأ بـ`https://`؛ أطوال الحقول كما في الجدول؛ `approved` boolean
    ولا يكون true إلا إذا كان الكاتب أدمن؛ `$other` → validate false.

قبل النشر: اتّباع [[netagent-firebase-rules]] (مقارنة حيّة، نسخة احتياطية،
اختبار Emulator، ثم نشر بموافقة صريحة).

## 6. الواجهة (UI)

**الشريط السفلي:** تعديل `DashboardBottomBar._items[3]` من
`(Icons.bar_chart_rounded, 'التقارير')` إلى
`(Icons.storefront_rounded, 'المشتريات')`، وتعديل `_onBottomNavigation`
(في `dashboard_screen.dart` و`subscribers_screen.dart`) ليفتح الفهرس 3
شاشة `StoresScreen` بدل `QuickReportsScreen`.

**`StoresScreen`** (`lib/screens/stores_screen.dart`):
- قائمة المتاجر **المعتمدة** (شعار + اسم + مالك + وصف)، مع بحث بالاسم.
- زر **«أضف متجري»** → `StoreFormDialog` (اسم، رابط، وشعار/واتساب/وصف
  اختياري). عند الإرسال: `approved:false`, `ownerUid=me`، ورسالة
  «بانتظار موافقة الإدارة».
- يرى الوكيل متجره الخاص (حتى لو غير معتمد) بوسم **«قيد المراجعة»** مع
  تعديل/حذف.
- **الأدمن:** قسم «قيد المراجعة» يعرض الطلبات مع **اعتماد / رفض (حذف)**.
- الضغط على متجر → `StoreWebViewScreen`.

**`StoreWebViewScreen`** (`webview_flutter`): يحمّل `url` مع مؤشّر تحميل
وزر رجوع/تحديث/فتح في المتصفح، ومعالجة الأخطاء. على `kIsWeb` نفتح الرابط
في تبويب خارجي بدل WebView.

## 7. الخدمة (`lib/services/store_directory_service.dart`)

- `Store` (نموذج + `fromSnapshot(key, value)` + `logo` fallback favicon).
- `load()`: يقرأ `stores`؛ للوكيل يُرجع المعتمدة + متجره المعلّق؛ للأدمن
  الكل. يرتّب بالاسم.
- `submit({name,url,logoUrl?,whatsapp?,description?})`: يكتب متجراً جديداً
  `approved:false`, `ownerUid`, `ownerName` من ملف الوكيل.
- `updateOwn(key, {...})` / `deleteOwn(key)` للمالك.
- `approve(key)` / `deleteAny(key)` للأدمن.
- دوال الترشيح النقيّة (approved/own) قابلة للاختبار دون Firebase.

## 8. الاختبارات

- **وحدة** (`test/store_directory_service_test.dart`): تحليل اللقطة، شعار
  fallback، ترشيح (المعتمدة + متجر المالك المعلّق؛ استبعاد معلّقات الغير).
- **قواعد Emulator** (`tool/store_rules_test.mjs` على نمط
  `sas_directory_rules_test.mjs`): الوكيل يضيف متجره غير معتمد؛ لا يعتمد
  نفسه؛ لا يكتب متجر غيره؛ لا يقرأ غير الوكلاء؛ الأدمن يعتمد/يحذف.
- **واجهة** (`test/stores_screen_test.dart`): تظهر المعتمدة؛ متجر المالك
  بوسم «قيد المراجعة»؛ نافذة الإضافة تحفظ معلّقاً.

## 9. النطاق والمراحل (YAGNI)

**MVP (هذا السبينت):** الدليل + الإضافة + اعتماد الأدمن + WebView + تبديل
الشريط السفلي.

**مؤجّل:** التصنيفات، التقييمات/المراجعات، سحب المنتجات (غير ممكن بلا API)،
السلة/الدفع داخل التطبيق، تعدّد المتاجر لكل وكيل، إشعار الوكيل عند الاعتماد.

## 10. الأمان والخصوصية

- معلومات متجر عامة فقط؛ لا اعتمادات.
- اعتماد الأدمن يمنع الإساءة/السبام.
- WebView يفتح محتوى خارجياً (https فقط)؛ لا حقن بيانات التطبيق فيه.
- زر واتساب يفتح `wa.me` إن وُجد الرقم.
